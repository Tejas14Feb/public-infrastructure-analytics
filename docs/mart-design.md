# Mart design

Design for the intermediate and mart layers, decided after building and
testing the staging models. Each decision is backed by a data check.

## Decision 1: Sector and program

- **Sector comes from the awarding sub-agency**, mapped through a seed.
  It is complete for every transaction, including contracts.
- **Program comes from the assistance listing number**, as a drill-down
  below sector. Contracts show as "No program (contract)."
- **Display title: the most recent title** for each program number
  (a Type 1 slowly changing attribute).

Why:
- 106 programs exist, but spending is concentrated: one program (20.205,
  Highway Planning and Construction) holds about half of all dollars.
- One program number can carry several titles over time (20.106 had four),
  so grouping must use the number, not the title.
- One program (20.933) appears under both highways and transit, so a
  program-based sector would misclassify it.
- Contracts have no assistance listing (about $550M of FAA contracts alone).

## Decision 2: Recipients

- **Keyed by Recipient UEI**, using USAspending's recipient name.
- **Missing UEIs are labeled "Unknown recipient"** so their dollars stay
  in totals.

Why:
- UEI is present on all but 5 of 78,341 transactions, including years
  before the 2022 switch to UEI.
- Every UEI has exactly one name, so no name cleanup is needed.
- Name variants like "State of South Dakota" and "State of South Dakota
  Department of Transportation" are separately registered entities, each
  with its own UEI. UEI represents the legal entity that received the money.

## Decision 3: Star schema

| Table | One row per | Key |
|---|---|---|
| `fct_transactions` | Transaction | `transaction_key` (surrogate) |
| `dim_awards` | Award | `award_key` |
| `dim_recipients` | Recipient | `recipient_uei` |
| `dim_agencies` | Sub-agency | sub-agency name |
| `dim_programs` | Program | assistance listing number |
| `dim_geography` | State | `state_code` |
| `dim_dates` | Calendar day | date |

- Dimensions use natural keys, since each has a stable real-world ID.
- `dim_awards` reduces award staging (one row per award, state, and fiscal
  year) to one row per award.
- `dim_dates` is generated by dbt, with fiscal year and quarter attributes.

## Decision 4: Summary marts

| Business question | Mart | One row per |
|---|---|---|
| Where is the money going? | `mart_spending_by_state_sector` | State, sector, fiscal year |
| What changed after the infrastructure bill? | `mart_spending_trends` | Sector, fiscal year, with a Before/After period label |
| Who wins the work? | `mart_top_contract_recipients` | Recipient, state, fiscal year (contracts) |

- **Before:** FY2019–FY2021. **After:** FY2022 onward (the bill was signed
  in November 2021, at the start of FY2022).
- **Pandemic relief** is handled by comparing sectors: in FY2020, transit
  obligations rose 162% and aviation 169%, while highways rose 13%.
  Highways alone give the clearest before/after signal.
- **Later enhancement:** flag COVID relief exactly, using USAspending's
  disaster emergency fund codes.
